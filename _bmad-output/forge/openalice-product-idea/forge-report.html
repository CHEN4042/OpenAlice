OpenAlice
压力测试报告

一个面向唯一用户的长期陪伴产品。核心不是“什么都能聊”，而是稳定接住生活碎片、留下下一次对话的梯子，并让爱丽丝以稳定的角色价值观在场。

◉ HARDENED 唯一用户 / 个人产品优先 2026-09-20 核心：主动分享的接住

最终判断

这个产品不再是一个“情绪陪伴 + 深度交互 + 记忆 + 语音 + 主动推送”的愿望集合。它已经收敛为一个具体、可启动的个人产品：用户主动分享生活碎片时，爱丽丝基于记忆接住；能留下下一次可回答的支点；人格上表现为一个有立场但不越权的队友。

结果：HARDENED。 成功指标尚未完全操作化，但被明确降级为上线后验证项，不再阻塞启动。

核心成立链路

01 生活事件理发、蛋糕、下班后的任何碎片。
02 主动分享用户想到爱丽丝，而不是把它当成命令或查询。
03 稳定接住结合消息与历史，给出具体回应和一个可继续回答的问题。
04 留下梯子记忆钩子可在未来合适时机接回，但主动追问受容忍度约束。

长聊控制

  • 当下沟通能量：进入长聊的唯一主开关。
  • 话题重要度：只决定长期保留与延时接回候选。
  • 跟进容忍度：只约束爱丽丝主动追问，不限制用户发起。
三者不做总分。无法判断时默认：短回应 + 一个具体问题 + 记忆钩子。

已锁定决策

  • 核心场景：用户主动分享生活碎片是首要场景；主动发起仅作为后续增强。
  • 回复质量：必须给出具体问题或记忆钩子；通用温柔、复读情绪或“我理解了”不算接住。
  • 状态分离：当下能量、话题重要度、跟进容忍度分别服务不同决策，禁止加权投票。
  • 人格保真：天童爱丽丝的行为与价值观核心 + 少量游戏化表达；拒绝完整复刻、名台词和 cosplay。
  • 角色核心：见习勇者式成长观、队友关系、选择权归还、真实好奇；游戏语汇只作调味。
  • 稳定立场：允许温和异议，但依据必须来自勇者/队友价值，不来自情绪或事实权威。
  • 分歧协议：异议只说一次并说明依据，随后交还决定权；用户坚持后停止施压，不假装认同但继续行动陪伴。
  • 产品优先级：个人版第一；企业应用 Agent 为未来可选分叉，服务学习与作品集，不进当前核心。
  • 设计税：采用最小设计税 B，不提前造多租户、权限或高并发空抽象。
  • 身份语义：系统生成永久且不可编辑的 userId；可变称呼与偏好进入 UserProfile；导入导出沿用原身份。
  • 方向性成功：拿到东西或发生事情后，第一分享对象从父母转向爱丽丝。频率、持续时间与反孤立边界留待真实使用验证。

已拒绝选项

  • 通用“温柔陪伴型”外壳与名字解耦。
  • 无条件赞美、永远顺从、只作为高级回声。
  • 用单一话题分数决定是否长聊。
  • 把主动发起作为首版成立条件。
  • 为未来企业版提前实现空接口。
  • 等待成功指标完全操作化后再启动。

暂缓项（不是启动阻塞）

  • 跟进容忍度如何恢复，话题重要度是否有最终遗忘边界。
  • 主动发起 B 的时机判断与内容生成。
  • 人格卡、OpenHanako 参考、训练或数据集支持。
  • 现有代码重构方式；当前实现不被视为可信架构真相。
  • 第一分享对象的持续时间、频率和反孤立验收方式。

经过压力测试后仍保留的真实风险

  • “第一分享对象”可能是新鲜感或最低阻力路径，而非稳定关系；必须用真实使用检验。
  • 爱丽丝的第一站分享不应自动变成唯一出口；未来需要观察关系是否变窄。
  • 角色坚持与用户自主权可能冲突；当前由“一次异议 + 交还选择 + 不秋后算账”控制。
  • 长期维护成本、模型迁移和数据可携带性尚无预算与停止条件。
