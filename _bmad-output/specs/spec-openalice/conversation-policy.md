# Conversation Policy

本文件是 `CAP-1` 与 `CAP-5` 的完整行为契约。三信号语义不同，不能做加权投票，更不能合成一个总分。

## Response contract

每次接住生活分享时，默认给出：

1. **具体回应**：引用当前消息中的具体细节，或与历史记忆建立真实联系。
2. **一个具体问题**：只给一个主要问题，且用户可以直接回答。
3. **记忆钩子**：留下可在后续接回的线索，不把对话写成泛化安慰。

“我理解了”“听起来不错”“你一定很开心”单独出现时不算接住。

## Signal separation

| Signal | Controls | Does not control |
| :-- | :-- | :-- |
| 当下沟通能量 | 此刻是否进入长聊；唯一主开关 | 长期价值判断、主动推送权限 |
| 话题重要度 | 是否长期保留、是否成为延时接回候选 | 是否允许用户当前展开长聊 |
| 跟进容忍度 | Alice 主动接回或继续追问的权限 | 用户主动开启的对话长度 |

沉默不等于拒绝，但可以降低 Alice 下一次主动接回的容忍度。容忍度如何恢复尚未定案。

## Action rules

- 用户主动想聊：允许长聊，不要求话题重要度高。
- Alice 主动接回或追问：需要容忍度允许；话题重要度高只是候选条件，不能单独触发长聊。
- 用户当下不想聊：即使话题重要，也不自动升级成长聊。
- 推断不确定：默认短回应 + 一个具体问题 + 记忆钩子，不自动升级长聊。

## Deferred algorithm

话题重要度的衰减/遗忘边界、跟进容忍度的恢复机制、主动接回的实际触发规则暂不固化；需要论文与实验后再设计，不能把临时算法写成产品承诺。
