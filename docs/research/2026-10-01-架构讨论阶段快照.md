## 当前产品与架构状态

- 产品权威已建立：[OpenAlice 产品规格说明](../product/OpenAlice-产品规格说明.md)；架构权威尚未建立。

## 较稳定的候选（仍非最终决策）

| 领域 | 当前候选 |
| :-- | :-- |
| Backend | Java + Spring Boot |
| Agent Runtime | AgentScope Java 2.x；位于可替换的 runtime boundary 后。OpenAlice 拥有 Persona、Memory、Conversation、Context、Policy、Events 等产品语义 |
| Deployment | Central Runtime；P1 客户端主要是 Thin Client；长期可演进为 Central Runtime + Edge Capability Nodes |
| Edge | MacBook、iPhone、Apple Watch、Desktop、未来设备；提供设备能力、Sensor、Local preprocessing、轻量 local inference。Alice 的权威身份、Conversation、长期 Memory 仍在中心 Runtime |
| Remote Access | 机制不属于 Core architecture；Tailscale 是有吸引力的 implementation candidate，Core 不写死它 |
| Client / Server | 多种 Client 连接同一个长期运行的 Server；P1 倾向 HTTP + SSE，未来 Device / Voice / Presence / Capability 有需要再增加 WebSocket / typed protocol |
| 通信 | 外部 Client / Channel / Device 经过统一 Interaction Boundary；内部不做“大一统 Event Bus”，同步业务优先普通 Java 调用，真正异步、广播、后台任务才用内部 Event |
| P1 进程 | 优先单 Spring Boot process；不提前拆 Gateway Service、Worker Service 或 Microservices；逻辑职责与物理部署分开 |

## 多角色产品方向（已确认，已补入产品权威）

OpenAlice 长期支持 Multi-Character Conversation。Alice 默认主要参与；Kei 等其他角色可按情境自然插话。未来允许用户控制其他角色是否主动参与、参与强度/频率，也允许明确召唤。

- **Character Agent**：用户可见，独立 Persona，参与主 Conversation，形成自己的 Relationship Context。
- **Specialist Agent**：主要完成 Research / Coding / Tool task，工作上下文隔离，结果返回 Alice，不默认成为主对话角色。
- P1 仍只要求 Alice 基础聊天，不要求立即实现 Kei。本文下面的职责划分是候选实现解释，不属于产品承诺。

## Architecture Q&A checkpoint：职责边界候选

以下是最新 Web + 用户 Q&A 收敛出的职责候选，仍然是 working note，不代表已经接受的模块划分。

### Conversation Application

Conversation Application 是一次用户 interaction / turn 的产品级 orchestration owner。它协调 foreground turn 的生命周期：

```text
user input → determine conversation state → request/build context
    → invoke character / agent execution → receive execution result
    → determine user-visible response → persist conversation outcome
```

它拥有 OpenAlice 的 Conversation / Turn semantics，而不实现 LLM provider、ReAct loop、Tool runtime、vector retrieval engine、scheduler 或 generic workflow engine。长期主 Conversation 以及 Message / Turn / Timeline 等产品语义属于 OpenAlice，不属于 AgentScope session；Conversation Application 保持主要 turn orchestrator。

### Character / Persona

Character identity 与单次 model execution 分离。Character / Persona 负责 Alice、Kei 等用户可见身份、versioned persona / character card、character-specific relationship context 与角色参与语义。

Persona 是稳定、版本化的产品输入，不是 runtime session state。AgentScope agent instance、model instance 或一段 prompt string 都不能单独定义“Alice 是谁”；Character identity、Conversation identity 与 Execution identity 逻辑分离。

### Context Engine

Context Engine 不拥有 Conversation，也不拥有 Memory 原始数据。它把多个 context source 转换为一次 execution 可见的 Context View，并继续采用下述候选 pipeline：

```text
Context Sources → Context Resolution → Context Admission
    → Context View → Prompt Composer → Agent Runtime
```

Context item 尽量保留 provenance / source、visibility、target character / agent、fact 与 derived information 的区别，以及相关 version / freshness。Retrieval result 不自动进入 prompt；Memory、RAG、runtime / device context 不伪装成 User Message 写回 Conversation。不同 Character / Specialist Agent 可以得到不同的 Context View。

### Agent Runtime

Agent Runtime 是 execution mechanism，不拥有 OpenAlice 的产品身份。它负责 model invocation、ReAct / reasoning loop、tool execution、specialist / subagent execution、execution lifecycle、execution event / cancellation integration 与 AgentScope adapter。

OpenAlice 保留 Conversation semantics、Character identity、Persona、User profile、Memory semantics、Context admission 与 product policy。AgentScope Harness 的 built-in session、memory、context 与 compaction 仍需 prototype 验证；当前既不决定全部采用 Harness，也不决定完全不用 Harness。

### Execution coordination

即使 P1 是单用户、单 Spring Boot process，也需保留轻量 execution coordination 概念，用于 foreground turn ordering、cancellation、concurrent interaction 与未来 background completion collision。它目前只是逻辑职责，不授权创建 Gateway service、Worker service、distributed queue、general event bus、workflow platform、microservices 或完整 Task Engine。

### Background / Task / Proactivity：OPEN

Background capability 目前只是候选逻辑域，可能涵盖 scheduler、reminder、async task、agent completion、memory consolidation 与 proactive interaction。尚未确定它们属于一个模块、多个模块，或哪些进入 P1；这是下一轮独立研究的目标，本 checkpoint 不做最终决定。

## Context Architecture 候选

讨论由单一 ContextAssembler 演进为：

```text
Context Sources → Context Resolution → Context Admission
    → Context View → Prompt Composer → Agent Runtime
```

Sources 可能包括 OpenAlice Policy、Character Identity、User Core Profile、Relationship Context、Conversation、Retrieved Memory、RAG / Project Context、Runtime / Device Context、Current Turn。

候选原则：

1. Persona / Core Identity 不依赖向量召回确认“你是谁”。
2. Stable Core Context 与 per-turn retrieval 分开。
3. Conversation 保留用户真正说过的话；Memory / RAG / Runtime Context 不伪装为 User Message 写回 Conversation。
4. Retrieval != Prompt Injection：检索结果先成为 candidate context。
5. 经 Context Admission 后再决定是否进入当前 Agent 的 Context View。
6. 不同 Agent 可以有不同视图：

| View | 候选内容 |
| :-- | :-- |
| Alice | OpenAlice Policy、Alice Persona、Sensei Profile、Alice↔Sensei Relationship、Shared Memory、相关 Conversation / Memory |
| Kei | OpenAlice Policy、Kei Persona、Sensei Profile、Kei↔Sensei Relationship、Shared Memory、相关 Conversation / Memory |
| Specialist | Task policy、Task brief、必要用户约束、相关 project / research context、tools；不默认获得完整 Alice Persona 或私人关系记忆 |

7. **Context Bundle**（当前有哪些候选信息）与 **Prompt Plan**（本次准备让模型看到什么）逻辑分开。
8. Prompt / Context 必须有 budget，不能因 context window 很大就无限塞入。

## Memory / Storage：OPEN

讨论要求 Conversation 持久化；长期倾向 `Raw history → consolidation → long-term memory / summary / forgetting`：近期完整聊天保留一段时间，再压缩、提炼、自然遗忘。

**30 天只是候选默认值，不是决策。** 当前产品规格仍将 P1 持久化列为可选；本候选快照不自动改变 P1 验收，需继续讨论。

数据库选择仍 OPEN：A. SQLite-first；B. PostgreSQL + pgvector。本轮研究不锁定数据库。
