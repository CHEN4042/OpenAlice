- (decision) 以 bmad-forge-idea 的 HARDENED 结论为唯一产品输入，不再重开核心方向讨论；本轮只做规格收敛与实施。
- (capability) CAP-1 用户可以通过文本分享生活碎片，爱丽丝必须结合当前消息和历史记忆给出“具体回应 + 一个具体问题 + 记忆钩子”；成功标准是理发/蛋糕等场景不会只剩泛化共情。
- (capability) CAP-2 用户的多轮对话必须持久保留，服务重启后仍能恢复同一会话历史；成功标准是重启前后继续对话时上下文仍存在。
- (capability) CAP-3 爱丽丝必须具备可辨识且稳定的角色行为：见习勇者、队友关系、少量游戏化表达、真实好奇，并能在四类核心情境中温和表达一次异议；成功标准见人格契约测试场景。
- (capability) CAP-4 系统必须区分稳定身份与可修改资料：系统生成永久隐藏的 userId，称呼/偏好/自我介绍进入可修改的 UserProfile；改名不改变历史归属。
- (capability) CAP-5 是否进入长聊由用户当下沟通意愿主导；话题重要度只影响长期保留与延时接回候选，跟进容忍度只约束爱丽丝主动追问；不确定时走短回应。算法细节后置。
- (constraint) 首版核心只做用户主动分享；主动发起 B 不作为首版成立条件，P1–P3 不主动推送。
- (constraint) 人格不接受通用“温柔陪伴型”外壳，也不做原作完整复刻、名台词或 cosplay；只保留行为与价值观核心加少量游戏语汇。
- (constraint) 单一话题分数不得加权决定是否长聊；长聊只能由当下沟通意愿主开关控制。
- (constraint) 个人版不为多租户、权限或高并发提前造空接口；企业应用分叉是低优先级后续学习项目。
- (constraint) P1 继续保持 Java 21、Spring Boot、AgentScope Java 2.0.2、单 Maven 模块、HTTP/SSE 文本链路与 PostgreSQL 唯一外部存储的方向。
- (constraint) 现有 ADR 是技术决策史；BMAD 只补产品层，不直接覆盖 docs/decisions 或生成并列架构体系。
- (non-goal) 首个实施切片不包含主动发起、语音、Web UI、工具调用、多用户、多人格、模型训练或数据集。
- (non-goal) 首个实施切片不实现话题重要度衰减、跟进容忍度恢复、主动接回触发算法；只保留策略边界。
- (assumption) 首版以文本为唯一交互通道；第一分享对象变化作为上线后的方向性成功验证，不在启动前追求完全操作化。
- (assumption) 当前代码只作参考，允许后续按 SPEC 和 ADR 重构，不把既有实现视为架构真相。
- (question) 人格资产的首次实现是继续使用工程配置中的 system prompt，还是立即落地独立 persona/ 文件与初始化流程？
- (question) 话题重要度的最终遗忘边界、跟进容忍度如何恢复，需要后续论文/实验支持，当前不固化。
